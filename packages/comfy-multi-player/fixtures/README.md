# Replay fixtures

The canonical cross-language parity contract is
`golden-vectors/conformance.json`; see [`docs/portability.md`](../docs/portability.md).
It references the session files below so every language runner consumes the
same inputs and recorded outputs rather than maintaining a private corpus.

Team-authored fixture corpus graduated from the V1-007 spike (no production
data). The sessions were generated by the real `comfy_cli.workflow_ops`
primitives against the prod object_info catalog, and each session file was
self-verified at generation time: replaying its op stream from its
`base_workflow` converges (under `workflow_ops.canonical`) onto its recorded
`workflow_final`.

## Provenance and drift verification

`MANIFEST.json` pins the source repository and exact comfy-cli commit used by
the V1-007 generator, the historical generator command and environment, and a
SHA-256 digest for every corpus data file. Each file also identifies the
generator path that produced it (or says that it was hand-authored). Run
`npm run verify:corpus` after any fixture change; the same command runs in CI
and fails for changed, missing, or unlisted fixture files.

The pinned source checkout is reproduced with:

```sh
git clone https://github.com/Comfy-Org/comfy-cli.git
cd comfy-cli
git checkout --detach 7e732242d971daf0d2d30f22f997abfacd78986e
uv sync --frozen
uv run <crdt-spike-checkout>/gen_fixtures.py
git -C <comfy-multi-player-checkout> diff -- fixtures/
```

The generator itself lived at `crdt-spike/gen_fixtures.py` in the historical
V1-007 workspace and was not graduated into either repository. Therefore the
last command requires an archived V1-007 spike checkout and is a documented
manual/nightly procedure, not a network-dependent CI job. Do not substitute a
new generator silently: archive it, record its exact command and runtime here,
update the pinned source SHA if appropriate, regenerate, inspect the fixture
diff, then update all manifest hashes. The frontend-only notes session remains
hand-authored as described below and must not be overwritten by Python.

Consumed by `test/replay.test.ts`: each session is replayed onto a doc minted
from the session's `base_workflow`, and the canonicalized projection must
deep-equal the canonicalized `workflow_final`
(canonical = nodes and links sorted by id — see
`docs/multiplayer-schema.md` §7).

## `<name>.session.jsonl`

One JSON object per line.

**Line 1 — header:**

```json
{"session": "<session id>", "authored_by": "<how it was authored>", "base_workflow": { ...workflow JSON the ops were minted against... }, "workflow_final": { ...workflow JSON after all ops... }}
```

Replay starts from `base_workflow` (never from an empty doc) and must end at
`workflow_final`.

**Lines 2..N — one stamped op per line**, in recorded order, exactly as minted
by comfy-cli's `workflow_ops` (`op`, `op_id`, `actor`, `base_version`,
`stamp: [base_version, actor]`, plus the kind-specific payload):

```json
{"op": "add_node", "op_id": "…", "actor": "cli", "base_version": 0, "stamp": [0, "cli"], "node_id": 4503599627370501, "class_type": "KSampler", "pos": [420, 180], "node": { … }}
{"op": "set_widget", "op_id": "…", "actor": "cli", "base_version": 1, "stamp": [1, "cli"], "node_id": 4503599627370501, "widget": "steps", "value": 30, "old": 20}
```

The sessions:

| File | Ops | Exercises |
|---|---|---|
| `session-large-build.session.jsonl` | 162 | full build-out: add_node/connect (incl. autogrow)/set_widget/delete_node |
| `session-edit-heavy.session.jsonl` | 61 | set_widget-dominated editing on an existing graph, plus the corpus's only `clear` — at index 36 of the stream, so this session is also what pins that the replay surface accepts a whole-document op mid-batch (`test/batch-policy.test.ts`) |
| `session-subgraph.session.jsonl` | 11 | subgraph-interior set_widget via all three address forms |
| `session-frontend-only-notes.session.jsonl` | 2 | `Note` + `MarkdownNote` — classes `object_info` never lists, so the pinned catalog cannot describe them (schema Amendment A2) |

`session-frontend-only-notes` is the one session NOT generated by comfy-cli:
its `base_workflow` and `workflow_final` are hand-authored (`authored_by` says
so), because the regression it pins is a mint/projection property, not a CLI
behavior. Base carries a `Note` and a `MarkdownNote`; the op stream adds a
second `MarkdownNote` (the applier's opaque path) and edits a catalogued
widget (proving ordinary ops still work in a note-bearing document). Its two
frontend-only classes MUST stay absent from `catalog.json` — `test/roundtrip.test.ts`
asserts that, so "fixing" notes by adding catalog entries fails loudly instead
of making the regression tests vacuous.

## `lww-vectors.json`

Six convergence vectors: `{comment, stamp_key, base_workflow,
subgraph_base_workflow, vectors}`. Each vector is `{name, note, ops,
converged_value, winner_op_id}` — the two ops applied in **both** orders must
converge on `converged_value` (recorded from `workflow_ops.apply_op`). The
`subgraph-flat-vs-nested` vector uses `subgraph_base_workflow`; the rest use
`base_workflow`. Stamp order: `[base_version, actor, op_id]`
(`docs/multiplayer-schema.md` §3).

## `catalog.json`

`{comment, types}` — per-class widget name→index order (`widget_order`) and
autogrow element-naming templates (`autogrow_templates`), exported from prod
object_info for the 10 node types the sessions use. This is the pinned
catalog the projection resolves the name-keyed `widgets` map against
(`docs/multiplayer-schema.md` §1.2/§7); apply needs it only for autogrow
collision renames.

## `findings.json`

Machine-captured spike findings, including the verbatim CLI error strings for
the subgraph op-scope probes (connect-to-interior, connect-to-promoted-widget,
delete-interior-node). Pinned as fixtures so error-contract drift is visible.
