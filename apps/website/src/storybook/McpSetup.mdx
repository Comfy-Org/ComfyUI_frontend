# Install the Storybook MCP

Connect Codex or Claude Code to this Storybook to discover approved marketing
components and stories from an agent conversation.

## Before you start

You need a verified `@comfy.org` Google account. You do not need to request or
manage a shared token.

Verify that the Codex CLI is available:

```bash
codex --version
```

If the Codex desktop app is installed on macOS but Terminal reports `command
not found`, expose the app's bundled CLI and restart the shell:

```bash
mkdir -p ~/.local/bin
ln -s /Applications/ChatGPT.app/Contents/Resources/codex ~/.local/bin/codex
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
exec zsh
```

If the link already exists, skip the `ln -s` command.

The remote MCP endpoint is:

```text
https://comfy-website-storybook-mcp.vercel.app/mcp
```

## Codex

Run:

```bash
codex mcp add comfy_marketing_storybook \
  --url https://comfy-website-storybook-mcp.vercel.app/mcp
```

Codex detects OAuth and opens the Comfy sign-in flow. Continue with your
`@comfy.org` Google account, return to Codex, then verify the saved
configuration:

```bash
codex mcp get comfy_marketing_storybook
```

## Claude Code

This experimental branch includes a project-level `.mcp.json`. After cloning
the repository, start Claude Code from the repository root and approve the
`comfy-marketing-storybook` server when prompted. Claude opens the Comfy sign-in
flow the first time it connects.

To install it for your user account without cloning the repository, run:

```bash
claude mcp add --scope user --transport http comfy-marketing-storybook \
  https://comfy-website-storybook-mcp.vercel.app/mcp
```

Then verify it:

```bash
claude mcp get comfy-marketing-storybook
```

## Test the connection

Start a new agent conversation and ask:

```text
Use the Comfy marketing Storybook MCP. List the documented website components,
then show me the available NodeBadge stories and their supported states.
```

A successful remote connection can read component and story documentation. It
cannot edit files, preview unbuilt local changes, or run local interaction and
accessibility tests.

## Local development tools

To author stories, preview changes, and run tests, start Storybook from the
repository root:

```bash
pnpm install
pnpm --filter @comfyorg/website storybook
```

Use `http://localhost:6008/mcp` as a separate local MCP server. The local server
does not use the shared bearer token.

## Troubleshooting

- **401 Authentication required:** run `codex mcp login
comfy_marketing_storybook` again, or reconnect the server in Claude Code.
- **Google sign-in is rejected:** use a verified `@comfy.org` account. Personal
  Google accounts cannot access this MCP.
- **Server is configured but unavailable:** restart the agent after adding the
  MCP configuration.
- **Documentation works but previews or tests do not:** the remote server is
  documentation-only. Start the local Storybook for development tools.
- **The browser asks for Google login:** this is expected. The client stores its
  own OAuth session after sign-in; no token needs to be copied.

## Security boundary

The Storybook UI and MCP endpoint require a verified `@comfy.org` Google
account. Each coworker authorizes their own client session. Anonymous and
non-Comfy requests are rejected, and the deployment is marked `noindex`.
