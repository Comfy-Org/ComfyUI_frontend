# Comfy website Storybook

This Storybook is the executable catalog for reusable components currently
shipped by the Comfy marketing website. It documents rendering, responsive
behavior, supported interactions, and accessibility expectations without
changing production pages.

## How to use it

1. Start with **Stable** components when composing a new page.
2. Open focused stories instead of inferring behavior from a default screenshot.
3. Use the viewport toolbar to review narrow and desktop layouts.
4. Use the Interactions panel to inspect supported behavior.
5. Use the Accessibility panel before approving a composition.
6. Treat missing variants as gaps, not permission to invent new anatomy.

## Catalog structure

- **UI** contains reusable controls.
- **Common** contains shared website components.
- **Blocks** contains reusable marketing sections.
- **Product** contains product-oriented compositions.
- **Compositions** contains isolated page previews assembled from existing parts.
- **Recipes** contains approved page structures for product, editorial, pricing,
  event, and model-launch work.

## Agent access

Codex and Claude can query the running Storybook through its MCP endpoint at
`/mcp`. The generated component catalog is available at
`/design-system/component-manifest.json`. Schema v2 records source and Figma
provenance, import paths, direct story and docs paths, supported states,
interaction and responsive coverage, capabilities, and composition safety.

Open **MCP Setup** in this section for copy-paste installation instructions for
the protected remote server and the full local development server.

The manifest also exposes five page recipes. An agent should choose cataloged
components from the recipe, preserve their complete anatomy, and treat an
unknown pattern as a component gap rather than generating a substitute.

The current coverage audit is available at
`/design-system/story-coverage.json`. Every uncataloged Vue file has a
disposition: page-local, template-local, compound part, icon, integration, or
reusable candidate. Only reusable candidates should be considered for future
promotion, and they still require an explicit contract.

Structural accessibility checks fail the story test suite. Color contrast is
reported in the Accessibility panel but remains a website-token review because
changing the shipped marketing palette is outside Storybook's scope.

## Review boundary

Stories demonstrate the shipped component API. Storybook-only fixtures,
viewports, tests, and compositions are not production routes. A defect that
requires changing a production component must be reviewed separately.
