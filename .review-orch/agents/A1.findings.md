# A1 CodeRabbit Review Findings

## Summary
This PR adds a new `RichComboWidget` with remote data fetching via TanStack Query, refactors the existing `useRemoteWidget` to use the shared query client, and introduces atomized `RemoteCombo` Vue components. Overall code quality is good with comprehensive tests.

### [Minor] Missing error handling for audio play Promise rejection
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:53
- **Issue:** The `el.play()` call returns a Promise that is handled with `.then()` but has no `.catch()` handler. If the play fails (e.g., autoplay policy), the Promise rejection is unhandled.
- **Fix:** Add `.catch()` handler or use void with error suppression:
```typescript
void el.play().then(() => {
  isPlaying.value = true
}).catch(() => {
  // Silently handle autoplay restrictions
})
```

### [Minor] Inconsistent props destructuring in Root.vue
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Root.vue:13
- **Issue:** Props are accessed via `props.context` but the project guidelines prefer reactive props destructuring. The `ctx` variable is assigned immediately from `props.context` without reactivity, which could cause issues if `context` prop changes.
- **Fix:** Use reactive props destructuring:
```typescript
const { context: ctx, multiple, disabled } = defineProps<{
  context: RemoteComboContext
  multiple?: boolean
  disabled?: boolean
}>()
```

### [Minor] Potential stale closure in watch callback
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:117-124
- **Issue:** The `applyAutoSelect` function captures `args.modelValue` which could be stale if the ref changes. While unlikely in current usage, this could cause issues with dynamic model binding.
- **Fix:** Access `args.modelValue` directly inside the function call rather than capturing it.

### [Nitpick] Inconsistent null vs undefined handling in query keys
- **File:** src/platform/remote/queryKeys.ts:17-20
- **Issue:** The query key uses `?? null` for workspaceId, userId, and apiKeyBucket. This is correct but the inconsistent use of `?? null` vs direct optional chaining elsewhere could lead to cache key mismatches.
- **Fix:** Document the expected nullish coalescing behavior or ensure consistent handling across all query key construction sites.

### [Nitpick] Type assertion in useRemoteCombo select callback
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:88
- **Issue:** The callback `rawItems.value.map((raw) => {...})` casts raw items without runtime validation when no schema is provided. If the API returns unexpected shapes, this could silently produce broken items.
- **Fix:** Consider adding defensive checks:
```typescript
return rawItems.value.map((raw) => {
  const val = String(raw ?? '')
  return { id: val, name: val }
})
```
The current code already handles this well; just noting for future consideration.
