# A12 Accessibility Review Findings

## Summary

This PR introduces a new `RemoteCombo` widget system with generally good accessibility practices. The components use reka-ui Combobox primitives which provide solid keyboard navigation and ARIA support out of the box. However, there are some accessibility concerns that should be addressed.

---

### [MINOR] Missing aria-describedby for error states on ComboboxTrigger
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Trigger.vue:34-65
- **Issue:** When `ctx.errorMessage.value` is truthy, the trigger shows an error state visually (via border color) but does not programmatically associate the error message with the trigger. Screen reader users will not know why the control is disabled.
- **Fix:** Add `aria-describedby` pointing to an error message element when in error state, or use `aria-invalid="true"` combined with error announcement.

---

### [MINOR] Audio preview button missing aria-live feedback
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:91-119
- **Issue:** The audio play/pause button correctly uses `aria-label` and `aria-pressed`, but when audio playback starts or stops, there is no live region announcement. Users relying on screen readers may not know the audio state changed.
- **Fix:** Consider adding a visually hidden `aria-live="polite"` region that announces "Audio playing" or "Audio paused" when the state changes.

---

### [MINOR] Video preview missing keyboard controls
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:80-89
- **Issue:** Video preview elements use `aria-label` but have no interactive controls for keyboard users to play/pause the video. While the video is muted and likely meant as a thumbnail preview, if the video autoplays on hover, keyboard-only users cannot control it.
- **Fix:** Either make the video purely decorative with `aria-hidden="true"` (if no interaction is expected), or add keyboard-accessible play/pause controls similar to the audio preview.

---

### [MINOR] FormDropdownMenuItem audio button lacks focus indicator
- **File:** src/renderer/extensions/vueNodes/widgets/components/form/dropdown/FormDropdownMenuItem.vue:163-191
- **Issue:** The audio preview button inside the dropdown menu item has hover styles but no explicit `focus-visible` styling. While the background changes on hover, keyboard users may not see a clear focus indicator.
- **Fix:** Add `focus-visible:ring-1 focus-visible:ring-ring focus-visible:outline-none` or similar focus styles to the button.

---

### [INFO] Good ARIA usage in RemoteCombo components
- **File:** Multiple RemoteCombo/*.vue files
- **Issue:** Not an issue - positive observation. The components correctly implement:
  - `role="alert"` and `aria-live="assertive"` on Error.vue
  - `role="status"` and `aria-busy="true"` on Loading.vue
  - `aria-live="polite"` on Empty.vue
  - `aria-label` with i18n interpolation on Trigger, Search, and Refresh buttons
  - `aria-pressed` on toggle buttons (LayoutSwitcher, audio play/pause)
  - `role="group"` with `aria-label` on LayoutSwitcher
  - `aria-hidden="true"` on decorative icons
- **Fix:** No fix needed - good accessibility practices.

---

### [INFO] i18n support for accessibility labels
- **File:** src/locales/en/main.json:2653-2665
- **Issue:** Not an issue - positive observation. The PR adds proper i18n strings for all accessibility-related labels including `selectAriaLabel`, `searchAriaLabel`, `layoutSwitcherAriaLabel`, `playAudioPreview`, and `pauseAudioPreview`.
- **Fix:** No fix needed.

---

### [INFO] Keyboard navigation handled by reka-ui primitives
- **File:** Multiple RemoteCombo/*.vue files
- **Issue:** Not an issue - positive observation. The component uses reka-ui's `ComboboxRoot`, `ComboboxTrigger`, `ComboboxInput`, `ComboboxContent`, `ComboboxItem`, etc., which provide built-in keyboard navigation (Arrow keys to navigate, Enter to select, Escape to close, typing to filter).
- **Fix:** No fix needed.
