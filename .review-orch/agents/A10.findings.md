# A10 Error Handling Review Findings

## Summary
Reviewed diff for empty catch blocks, swallowed errors, missing error boundaries, unhandled promise rejections, and missing try-catch around async operations.

---

### [MINOR] Empty catch block swallows audio play errors
- **File:** src/renderer/extensions/vueNodes/widgets/components/form/dropdown/FormDropdownMenuItem.vue (diff line ~3649)
- **Issue:** The audio play promise rejection is caught with an empty callback `void audio.play().catch(() => {})`. While audio play failures are often benign (user gesture requirements, etc.), completely swallowing the error prevents any logging or user feedback.
- **Fix:** Consider logging at debug level or updating UI state: `void audio.play().catch((e) => console.debug('Audio preview failed:', e))` or set a visual indicator that playback failed.

### [INFO] Audio component has proper event handling
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue (diff line ~2449)
- **Issue:** Unlike the FormDropdownMenuItem audio play, this implementation uses `.then()` to handle success and doesn't have an explicit catch. However, unhandled rejections from `el.play()` may propagate. The pattern here differs from the swallowed catch in FormDropdownMenuItem.
- **Fix:** Consider adding `.catch()` handler for consistency: `void el.play().then(() => { isPlaying.value = true }).catch(() => { isPlaying.value = false })`

The error handling in this PR is generally well-implemented:

2. The `isRetriableError` utility properly classifies errors for retry decisions
3. Error states are properly exposed to UI components via computed refs
