# A6 DX & Readability Review Findings

## Summary

Reviewed ~3000 lines of new/modified code introducing a remote combo widget system with TanStack Query integration. Overall clean implementation with good documentation on key functions. Found several minor naming and documentation issues.

---

### [LOW] Magic number needs documentation
- **File:** src/base/remote/diagnostics.ts:3
- **Issue:** `PAYLOAD_KEY_SAMPLE = 10` lacks documentation explaining why 10 is chosen as the limit for key sampling.
- **Fix:** Add a brief comment explaining the rationale (e.g., "Sample first 10 keys to keep diagnostic payloads small while providing useful debugging context").

---

### [LOW] Inconsistent function naming - "resolved" vs actual purpose
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Refresh.vue:31-32
- **Issue:** Variable `resolved` is ambiguous. It is named as if it resolves something, but it just selects between injected and prop context.
- **Fix:** Rename to `ctx` directly or `activeContext` to clarify it's the context being used.

---

### [LOW] Void expression could be clearer
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/LayoutSwitcher.vue:22
- **Issue:** `void props` used to suppress unused variable warning is unclear. The props are destructured but unused in setup.
- **Fix:** Either remove the unused props destructuring or add a brief comment explaining why props is accessed but not used in setup scope.

---

### [LOW] Confusing "emptyDisplayValue" naming
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Search.vue:18
- **Issue:** Function `emptyDisplayValue` returns empty string but name suggests it displays something when empty.
- **Fix:** Rename to `noDisplayValue` or `suppressDisplayValue` to clarify it prevents display.

---

### [LOW] Dead/redundant code - duplicate options access
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:64-65
- **Issue:** `config?.item_schema` is accessed twice - once to check if schema exists, then again inside the block.
- **Fix:** Store schema in a variable: `const schema = config?.item_schema; if (schema) { ... use schema ... }`

---

### [LOW] Missing JSDoc on public interface type
- **File:** src/platform/remote/schema/remoteRequestSchema.ts:3-11
- **Issue:** `RemoteRequestDescriptor` interface is a public API contract but lacks documentation explaining its purpose and field meanings.
- **Fix:** Add JSDoc describing the interface's role in the remote options system and document each field's purpose.

---

### [NITPICK] Inconsistent abbreviation usage
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/state.ts
- **Issue:** Uses full word `selectedValue` but abbreviates `isOpen`. Prefer consistency.
- **Fix:** Minor; either expand all or abbreviate consistently. Current state is acceptable.

### [NITPICK] Story file has commented-out ref import pattern
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/RemoteCombo.stories.ts:2

### [NITPICK] Context injection error messages could include component name
- **File:** Multiple RemoteCombo/*.vue files (Error.vue:12, Item.vue:28, Search.vue:15, Trigger.vue:13)
- **Issue:** Error messages say "must be used inside RemoteCombo.Root" but don't include which child component threw the error.
- **Fix:** Error messages already include the component name like "RemoteCombo.Error must be used...". This is good practice and already implemented.

### [LOW] Variable naming - "rawItems" vs "rawData"
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:49-58
- **Issue:** Inconsistent naming between `rawData` (from useRemoteOptions) and `rawItems` (extracted items). The relationship could be clearer.

---

### [LOW] Missing documentation on preview URL resolution logic
- **File:** src/base/remote/itemSchema.ts:33-49
- **Issue:** `resolvePreviewUrl` function handles multiple URL schemes (absolute, data:, blob:, relative) but lacks documentation explaining the resolution strategy.
- **Fix:** Add JSDoc explaining the URL resolution hierarchy and when base URL is applied.

---

### [LOW] Unused import type declaration pattern
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:17-18
- **Issue:** Props destructuring `const props = defineProps<{...}>()` then accessing `props.layout`, `props.class`, `props.item`, etc. Could use reactive destructuring per project conventions.
- **Fix:** Per AGENTS.md guidelines, prefer reactive props destructuring. Consider `const { item, index, layout, class: className } = defineProps<...>()`.
