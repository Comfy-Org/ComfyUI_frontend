# Security Audit Findings - A3 Security Auditor

## Summary
This PR introduces a remote combo widget feature with TanStack Query integration for fetching and displaying dropdown options from remote APIs. The security review focused on OWASP vulnerabilities, XSS, injection risks, exposed secrets, and CSRF concerns.

---

### [LOW] Unvalidated URL in Image/Video/Audio Preview Elements
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:72-91
- **Issue:** The `preview_url` from remote API responses is directly bound to `<img>`, `<video>`, and `<audio>` elements via `:src="item.preview_url"`. While this does not cause XSS (Vue escapes attributes), malicious URLs (e.g., tracking pixels, protocol handlers like `javascript:`) could be injected if the API is compromised or returns unexpected data.
- **Fix:** Consider validating that `preview_url` matches an allowlist of expected protocols (http, https, data:, blob:) before rendering. The `resolvePreviewUrl` function already handles some normalization but does not reject dangerous protocols.

---

### [INFO] Proper Sanitization of Error Details
- **File:** src/base/remote/diagnostics.ts:5-31
- **Issue:** The `summarizeError` function correctly strips sensitive data (config, headers, request/response bodies) from Axios errors before logging. Test at line 1569 verifies secrets are not leaked.
- **Fix:** No action needed - this is a positive security finding.

---

### [INFO] API Key Bucket Partitioning for Cache
- **File:** src/platform/remote/queryKeys.ts:1-26
- **Issue:** Query keys properly partition by `apiKeyBucket` to prevent cache pollution between authenticated and anonymous sessions.
- **Fix:** No action needed - this is a positive security finding.

---

### [INFO] No v-html or innerHTML Usage
- **File:** All new Vue components
- **Issue:** No usage of `v-html`, `innerHTML`, or `dangerouslySetInnerHTML` found in any new components. All user-facing content is rendered through Vue's safe text interpolation.
- **Fix:** No action needed - this is a positive security finding.

---

### [INFO] Auth Header Handling
- **File:** src/platform/remote/composables/useRemoteOptions.ts:69-86
- **Issue:** Authentication headers are properly obtained via `authStore.getAuthHeader()` and only attached for `comfyApi` client requests. Headers are not logged or exposed in error messages.
- **Fix:** No action needed - follows secure patterns.

---

### [INFO] No Exposed Secrets in Code
- **File:** All diff files
- **Issue:** No hardcoded API keys, tokens, passwords, or credentials found. Test files contain mock tokens like `SECRET-TOKEN-123` that are used specifically to verify they are NOT leaked in error summaries.
- **Fix:** No action needed.
