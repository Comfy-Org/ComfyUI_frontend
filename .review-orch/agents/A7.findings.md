# A7 Test Quality Review Findings

## Summary
Review of test coverage and quality for PR-12163 (remote combo widget implementation).

---

### [MEDIUM] Missing test coverage for useRemoteCombo composable
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts
- **Issue:** The new `useRemoteCombo` composable (163 lines) has no dedicated unit tests. Tests exist only indirectly via `RichComboWidget.test.ts` integration tests. Key behaviors untested in isolation: `applyAutoSelect` logic, `searchIndex` building with `search_fields`, filtering behavior, error message handling, `previewType` derivation.
- **Fix:** Add `useRemoteCombo.test.ts` to cover the composable's contract directly, including: auto-select edge cases (empty array, single item), search field indexing, filter matching, and computed state derivation.

---

### [MEDIUM] Missing tests for diagnostics.ts utility
- **File:** src/base/remote/diagnostics.ts
- **Issue:** The `summarizeError` and `summarizePayload` functions are tested in `retryAndDiagnostics.test.ts`, but this file mixes concerns (retry logic + diagnostics). The diagnostics module itself has no standalone test file despite being its own module.
- **Fix:** Consider renaming test file to reflect its dual scope or splitting tests to match module boundaries for easier maintenance.

---

### [LOW] useRemoteOptions test coverage is shallow
- **File:** src/platform/remote/composables/useRemoteOptions.test.ts
- **Issue:** Tests only verify query key structure and disabled state behavior. Missing coverage for: actual fetch execution with mocked responses, error handling, retry behavior with `isRetriableError`, `refetch` and `invalidate` methods, `select` transform function.
- **Fix:** Add tests that mock `axios.get` responses and verify data flows through the composable correctly, including error states and retry behavior.

---

### [LOW] RemoteCombo component tests rely heavily on context mocking
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.preview.test.ts
- **Issue:** Tests create mock context objects with all refs/computeds manually constructed. While functional, this pattern can drift from actual context shape over time if `RemoteComboContext` interface changes. Tests may pass with outdated mocks.
- **Fix:** Consider creating a shared test utility that produces valid `RemoteComboContext` instances to ensure test mocks stay synchronized with interface changes.

---

### [LOW] Missing edge case tests for itemSchema functions
- **File:** src/base/remote/itemSchema.test.ts
- **Issue:** Good coverage overall, but missing tests for: deeply nested array paths (e.g., `data.0.nested.1.value`), empty string handling in `resolveLabel` templates, malformed preview URLs, circular structure handling in `getByPath`.
- **Fix:** Add edge case tests for complex nested paths and malformed input data.

---

### [LOW] widgetTestUtils utility introduced without tests
- **File:** src/renderer/extensions/vueNodes/widgets/components/widgetTestUtils.ts (referenced in RichComboWidget.test.ts)
- **Issue:** `createMockWidget` utility is used in tests but the utility file itself has no validation tests to ensure mock shape correctness.
- **Fix:** Document expected mock shape or add minimal tests ensuring mock conforms to `SimplifiedWidget` interface.
