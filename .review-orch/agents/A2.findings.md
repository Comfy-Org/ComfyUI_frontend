# A2 Bug Hunter Review Findings

## Summary
Reviewed new remote combo widget system including TanStack Query integration, remote data fetching, schema validation, and UI components.

---

### [MEDIUM] Potential race condition in auto-select watch

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:130-138
- **Issue:** The `watch` on `items` with `immediate: true` may trigger `applyAutoSelect` before `modelValue` is correctly hydrated from the graph's serialized state. If items load fast and the widget has a saved value, this could overwrite it.
- **Fix:** Add a guard checking if the component has been fully mounted/hydrated before auto-selecting, or check if `modelValue` was explicitly set from serialization before overwriting.

---

### [LOW] Missing null check in toggleAudio

- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Item.vue:45-56
- **Issue:** The `toggleAudio` function calls `el.play()` without checking if the audio source is valid. If `preview_url` is an invalid or unloadable URL, the promise will reject but the `isPlaying` state may be inconsistent.
- **Fix:** Add error handling to the play() promise:
```typescript
void el.play().then(() => {
  isPlaying.value = true
}).catch(() => {
  isPlaying.value = false
})
```

---

### [LOW] Unchecked array access in applyAutoSelect

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:121-127
- **Issue:** While `list.length === 0` check exists, accessing `list[0]` and `list[list.length - 1]` could be problematic if `list` is a reactive computed that changes between the check and access in edge cases.
- **Fix:** Store the length check result and use optional chaining: `list[0]?.id` to be defensive.

---

### [MEDIUM] Singleton QueryClient may cause test pollution

- **File:** src/platform/remote/queryClient.ts:29-43
- **Issue:** The `appQueryClient` is stored at module scope. The `getAppQueryClient()` lazily creates a new client if none exists, but if `createAppQueryClient()` is called multiple times (e.g., in HMR scenarios), previous cache data could be orphaned. Tests also need to be careful to isolate the singleton.
- **Fix:** Consider adding a `resetAppQueryClient()` function for testing/HMR cleanup, or use a WeakRef pattern to allow GC of old clients.

---

### [LOW] Error message not internationalized fully

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteOptions.ts:102
- **Issue:** The error message thrown is hardcoded English: `'useRemoteOptions: descriptor is required'`. While this is a developer error, it's inconsistent with the i18n approach elsewhere.
- **Fix:** Consider removing the error (since enabled guards it) or using a consistent error pattern.

---

### [LOW] Potential stale closure in useRemoteWidget

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteWidget.ts:75-88
- **Issue:** The `getQueryKey()` function is called inside `fetchValue()` and captures `useAuthStore().userId` and `useApiKeyAuthStore().getApiKey()` at call time. If auth state changes during an in-flight request, the cache key used for storing results may differ from subsequent lookups.
- **Fix:** Ensure query key is computed at the start of the operation and used consistently throughout, or invalidate on auth changes.

---

### [MEDIUM] Missing AbortController cleanup in useRemoteOptions

- **File:** src/platform/remote/composables/useRemoteOptions.ts:92-110
- **Issue:** The `executeRemoteRequest` function receives a signal from TanStack Query, but if the component is unmounted while auth headers are being fetched (async operation before axios call), the abort may not be respected.
- **Fix:** Check `signal.aborted` after the await for `getAuthHeader()`:
```typescript
const authHeader = await authStore.getAuthHeader()
if (signal.aborted) throw new DOMException('Aborted', 'AbortError')
```

---

### [LOW] Implicit empty string coercion

- **File:** src/base/remote/itemSchema.ts:58
- **Issue:** When `preview_url_field` is set but resolves to `undefined` or `null`, the code does `String(getByPath(raw, schema.preview_url_field) ?? '')` which converts it to an empty string. `resolvePreviewUrl('')` returns `undefined` (correct), but this creates a confusing intermediate state.
- **Fix:** Check for falsy value before calling String():
```typescript
const rawValue = getByPath(raw, schema.preview_url_field)
const previewRaw = rawValue ? String(rawValue) : undefined
```

---

### [LOW] Computed staleTime may cause issues

- **File:** src/platform/remote/composables/useRemoteOptions.ts:107
- **Issue:** `staleTime: computed(() => toValue(args.descriptor)?.ttl ?? 0)` - TanStack Query expects a number, but passing a computed ref here may not work as expected depending on how TanStack handles it.
- **Fix:** Verify TanStack Query v5 supports reactive staleTime, or unwrap the computed value.
