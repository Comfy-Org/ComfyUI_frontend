# A14 Vue Patterns Review - Remote Combo Widget

## Summary
Reviewed Composition API usage, reactivity patterns, and Vue best practices across new Vue components and composables for the remote combo widget feature.

---

### [MINOR] Non-reactive context access in Root.vue
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Root.vue:13
- **Issue:** `const ctx = props.context` loses reactivity if `props.context` changes after component mount. While unlikely in this use case since context is typically stable, the pattern could cause issues if context is ever swapped.
- **Fix:** Access `props.context` directly in template/handlers or use `toRef(props, 'context')` if reactive changes are expected.

---

### [MINOR] Synchronous throw in inject pattern
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/Error.vue:11-13, Item.vue:31-33, Search.vue:18-20, Trigger.vue:21-23
- **Issue:** Multiple components throw synchronously during setup if `inject(RemoteComboKey)` returns null. While this is intentional for catching misuse, Vue's error handling may not gracefully surface these errors in all contexts.
- **Fix:** Consider using `inject(RemoteComboKey, null)` with a more graceful fallback or Vue's `onErrorCaptured` for better developer experience, or document the requirement clearly.

The Vue patterns in this PR are well-implemented. The code follows Vue 3.5+ best practices including:
- Proper use of Composition API with `<script setup>`
- Correct reactive state management with `ref`, `computed`, and `watch`
- Proper `v-for` key usage
- No props mutation
- Good use of `defineModel` and `defineProps` with destructuring defaults
- Proper use of `inject/provide` for component communication

Minor suggestions are primarily stylistic or for improved error handling robustness.
