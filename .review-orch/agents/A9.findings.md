# A9 DDD Structure Review - Remote Combo Widget

## Summary
This PR introduces a new remote combo widget system with good domain layering overall. The architecture follows a clean separation with `base/remote/` for domain logic, `platform/remote/` for infrastructure, and `renderer/extensions/vueNodes/widgets/` for UI. However, there are several areas that could benefit from improved domain boundaries.

---

### [LOW] Domain Logic in UI Layer - Preview URL Resolution
- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteCombo.ts:65-68
- **Issue:** The composable imports `getComfyApiBaseUrl()` and resolves preview URLs directly. URL resolution is infrastructure/domain logic that should not be in the widget composable.
- **Fix:** Move `previewBaseUrl` resolution into `useRemoteOptions` or create a dedicated service. The composable should receive the resolved base URL via dependency injection or context.

---

### [LOW] Anemic Domain Model - DropdownItemShape
- **File:** src/base/remote/itemSchema.ts:3-8
- **Issue:** `DropdownItemShape` is a plain data interface with no behavior. The `displayName()` function is separate, which is characteristic of an anemic domain model. While acceptable for DTOs, this loses cohesion.
- **Fix:** Consider creating a `DropdownItem` class with `displayName()` as a method, or document that this is intentionally a DTO pattern. The current approach works but is worth noting.

---

### [LOW] Cross-Domain Import in Platform Layer
- **File:** src/platform/remote/composables/useRemoteOptions.ts:14
- **Issue:** `useApiKeyAuthStore` is imported from `@/stores/apiKeyAuthStore`. The platform remote layer depends on the general stores layer, creating a cross-domain dependency.
- **Fix:** Inject auth scope via props/context rather than directly importing stores. The auth scope could be passed down from the widget layer.

---

### [INFO] Good Domain Separation - Base Remote Layer
- **File:** src/base/remote/ (diagnostics.ts, itemSchema.ts, retry.ts)
- **Issue:** N/A - This is positive feedback
- **Fix:** The `base/remote/` directory provides pure domain utilities (`getByPath`, `resolveLabel`, `extractItems`, `buildSearchText`, retry logic, diagnostics) with no UI or framework dependencies. This is excellent DDD practice.

---

### [INFO] Good Layer Isolation - RemoteCombo Component Structure
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/
- **Issue:** N/A - This is positive feedback
- **Fix:** The atomic component structure (Root, Trigger, Content, Search, List, Item, Error, Loading, Empty, Refresh) follows good composition patterns. The state injection via `RemoteComboKey` properly isolates component concerns.

---

### [INFO] Schema Domain - Clean Validation
- **File:** src/schemas/nodeDefSchema.ts:130-136
- **Issue:** N/A - This is positive feedback
- **Fix:** The XOR refinement (`zComboInputOptionsValidated`) properly enforces that `remote` and `remote_combo` are mutually exclusive. This keeps schema validation logic in the schema domain.

---

### [LOW] Missing Domain Boundary - Widget Adapter Pattern
- **File:** src/renderer/extensions/vueNodes/widgets/adapters/specAdapter.ts
- **Issue:** The adapter pattern is introduced but only `comboAdapter` exists. The interface references Vue `Component` type, mixing concerns.
- **Fix:** If this adapter pattern grows, consider separating the component registration from the prop extraction logic. For now, this is acceptable given the limited scope.

---

### [INFO] Query Key Factory Pattern
- **File:** src/platform/remote/queryKeys.ts
- **Issue:** N/A - This is positive feedback
- **Fix:** The `remoteOptionKeys` factory properly encapsulates query key construction, following TanStack Query best practices. The scope-based partitioning (userId, workspaceId, apiKeyBucket) is well-designed for cache isolation.

---

### [LOW] Flat Folder Potential - RemoteCombo Components
- **File:** src/renderer/extensions/vueNodes/widgets/components/RemoteCombo/
- **Issue:** 12 files in a single directory. While each file is focused, this is approaching the threshold where subdirectories might improve navigation (e.g., `atoms/`, `composites/`).
- **Fix:** Consider grouping: primitive atoms (Empty, Loading, Error) vs composite components (Item, Trigger, Search) if the folder grows further. Current state is acceptable.

---

### [INFO] Clean Test Organization
- **File:** src/base/remote/itemSchema.test.ts, itemSchema.property.test.ts
- **Issue:** N/A - This is positive feedback
- **Fix:** Property-based tests for `mapToDropdownItem` alongside unit tests demonstrates thorough domain testing. The separation of property tests into a dedicated file is a good practice.
