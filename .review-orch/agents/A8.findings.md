# A8 Ecosystem Compatibility Review - Remote Combo Widget

## Summary

This PR introduces a new `RichComboWidget` for remote-populated combo dropdowns with TanStack Query caching, replacing the old module-level cache in `useRemoteWidget`. The changes are largely additive, but there are several areas affecting custom node compatibility.

---

### [MEDIUM] useRemoteWidget API changes - cacheKey removed

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteWidget.ts:196
- **Issue:** The `cacheKey` property has been removed from the `useRemoteWidget` return object and replaced with `getQueryKey`. The `getCacheEntry` method was also removed. Custom nodes that directly access the widget cache via `cacheKey` or `getCacheEntry()` will break.
- **Fix:** Custom nodes should migrate to using `getQueryKey()` if they need cache key access. Document this breaking change in release notes. The new return type is a TanStack Query key array rather than a string.

---

### [LOW] Internal cache implementation replaced with TanStack Query

- **File:** src/renderer/extensions/vueNodes/widgets/composables/useRemoteWidget.ts:63-100
- **Issue:** The module-level `dataCache` Map has been replaced with TanStack Query's `QueryClient`. While the public `getValue`, `getCachedValue`, and `refreshValue` APIs remain compatible, any custom nodes that imported or monkey-patched the internal `dataCache` will no longer work.
- **Fix:** This is an internal implementation detail. Custom nodes should only use the public API. Consider documenting that internal cache access was never supported.

---

### [LOW] New schema field remote_combo added to ComboInputSpec

- **File:** src/schemas/nodeDefSchema.ts:127
- **Issue:** The `zComboInputOptions` schema now accepts a new optional `remote_combo` field alongside the existing `remote` field. A new validation (`zComboInputOptionsValidated`) enforces XOR between `remote` and `remote_combo`. Custom nodes that manually construct combo input specs should be aware of this constraint.
- **Fix:** No action needed for existing nodes. The XOR validation is only applied during node definition parsing, not at runtime. Document the new `remote_combo` option for node authors who want richer combo widgets.

---

### [INFO] New widget type RichComboWidget for remote_combo specs

- **File:** src/renderer/extensions/vueNodes/widgets/components/WidgetSelect.vue:2-4
- **Issue:** When a combo spec includes `remote_combo`, the new `RichComboWidget` renders instead of `WidgetSelectDropdown`. This is additive and does not affect existing nodes that use `remote` or static options.
- **Fix:** None needed. This is purely additive behavior.

---

### [INFO] FormDropdownMenuItem now supports description and audio preview

- **File:** src/renderer/extensions/vueNodes/widgets/components/form/dropdown/FormDropdownMenuItem.vue:28-72
- **Issue:** The `FormDropdownMenuItem` component now renders a `description` slot and audio preview playback. The `FormDropdownItem` type and `FormDropdownMenuItemProps` interface have been extended with optional `description` field. Existing custom components extending these types will continue to work.
- **Fix:** None needed. Changes are backward compatible.

---

### [INFO] FormDropdown gains showSort and showLayoutSwitcher props

- **File:** src/renderer/extensions/vueNodes/widgets/components/form/dropdown/FormDropdown.vue:36-37
- **Issue:** New optional props `showSort` and `showLayoutSwitcher` (both default to `true`) allow hiding the sort/layout controls. Custom nodes using FormDropdown are unaffected as defaults preserve existing behavior.
- **Fix:** None needed. Existing usage is unchanged.

---

### [INFO] New Vue Query plugin registered in main.ts

- **File:** src/main.ts:6-13
- **Issue:** The app now registers `VueQueryPlugin` with a shared `QueryClient`. This affects the global Vue app context but does not change behavior for existing custom nodes.
- **Fix:** None needed. This is infrastructure for the new remote combo feature.

---

## Breaking Change Summary

| Change | Severity | Migration Path |
|--------|----------|----------------|
| `useRemoteWidget().cacheKey` removed | Medium | Use `getQueryKey()` instead |
| `useRemoteWidget().getCacheEntry()` removed | Medium | Use TanStack Query's `queryClient.getQueryData()` |
| Internal `dataCache` Map removed | Low | Use public API only (was never documented) |

## Recommendations

1. Add migration notes in PR description and release notes about the `cacheKey` -> `getQueryKey()` change
2. If there are known custom nodes using these internals, consider adding a deprecation warning or temporary shim
3. The overall API surface (`getValue`, `getCachedValue`, `refreshValue`, `addRefreshButton`) remains stable - this is good for ecosystem compatibility
